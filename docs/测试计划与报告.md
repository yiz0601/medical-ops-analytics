### 1.4 术语与缩写

| 术语 | 含义 |
| --- | --- |
| ODS / DWD / DWS / ADS / DIM | 贴源层 / 明细层 / 汇总层 / 应用层 / 公共维表层 |
| 登记口径 | 就诊登记时的汇总费用字段（`his_outpatient.fee_amount`、`his_inpatient.total_fee`），1 就诊 1 行 |
| 流水口径 | 逐笔收费明细（`his_charge.amount`），1 收费项目 1 行 |
| 财务口径 | 财务日报导出数据（`finance_excel.revenue` 等），1 科室 × 1 日 1 行 |
| BLOCK / WARN | 质量规则级别：阻断级（阻断入库或下游）/ 告警级（记录并通知） |
| P0 / P1 / P2 | 用例优先级：P0 必测阻断项、P1 核心功能、P2 次要或增强 |
| 致命 / 严重 / 一般 / 轻微 | 缺陷严重级别，定义见 2.5.2 |
| 窗口首尾效应 | 数据建仓时间窗 2025-04-01~06-30 两端截断导致的统计偏差（K6） |
| NL2SQL | 自然语言转 SQL，用于智能问数 |
| RTO / RT | 响应时间（Response Time） |
| P95 | 95 分位响应时间 |
| pp | 百分点（percentage point），比率类指标容差单位 |

## 2. 测试策略

### 2.1 测试分层

| 层 | 测试类型 | 触发时机 | 责任角色 | 主要方法 | 判定依据 | 本版状态 |
| --- | --- | --- | --- | --- | --- | --- |
| L1 | 数据质量测试 | 每批次采集后 / 加工后 | 测试工程师 + 数据开发 | 规则脚本断言 + 明细比对 | `QR-DQ-01`~`20`、`QR-REC-*`、`QR-CHG-03` | **已执行（源文件实测）** |
| L2 | 指标口径测试 | 每批次指标计算后 | 测试工程师 | 固定统计期直接查明细重算，与 ADS 结果比对 | 《指标口径手册》第 5 章基线值 | 待阶段三 |
| L3 | 接口测试 | 阶段四接口联调 | 后端开发 + 测试 | pytest + httpx 契约测试、错误码穷举 | 《概要设计》第 8 章、5.2 错误码 | 未执行 |
| L4 | 功能测试 | 阶段四/五/六功能提测 | 测试工程师 | 等价类、边界值、场景法、探索式 | 《项目说明》第五章功能需求 | 未执行 |
| L5 | 性能测试 | 阶段七 | 性能测试 + 后端 | 负载/压力/浸泡/稳定性 | 《概要设计》第 11 章 | 未执行 |
| L6 | 安全测试 | 阶段七 | 安全测试 + 测试 | 越权矩阵、注入用例、脱敏核查、审计抽样 | 《概要设计》第 10 章 | 未执行 |
| L7 | 兼容性测试 | 阶段五/七 | 测试工程师 | 浏览器/分辨率矩阵 | 本文件 6.7 | 未执行 |
| L8 | 智能分析准确率测试 | 阶段六 | 测试工程师 + 算法 | 固定测试集 + 四维人工评分 | 《项目说明》第二章目标 5 | 未执行 |

**分层原则**

1. **下层不过，上层不做**：L1 数据质量未通过（存在 BLOCK 级失败）时，L2 指标断言无效，不启动 L3 及以上测试。
2. **口径唯一**：L2 的断言值只允许来自《指标口径手册》第 5 章，测试脚本不得自行定义期望值。
3. **可复算**：任何 L1/L2 的判定必须给出可复现的取数口径与算式（见 4.1、4.3）。
4. **回归友好**：每层用例编号稳定，便于阶段七回归时按编号复用。

### 3.3 异常结论的原因分析与处理建议

#### 3.3.1 异常一：住院日出院人次 2025-06-30 单日 190 例（告警）

**现象**

- 统计期 91 天，出院人次合计 1,500，日均 1,500 ÷ 91 = **16.48 ≈ 16.5 例/日**。
- 2025-06-30 单日出院 **190 例**，占全部 1,500 例的 190 ÷ 1,500 = **12.67%**。
- 单日值约为日均值的 190 ÷ 16.48 ≈ **11.5 倍**，远超 `QR-DQ-19` 的 ±20% 波动阈值，故判**告警**。

**原因分析（已定位，属数据集构造特征而非数据错误）**

1. **窗口截断压平**：数据以 `discharge_date = admit_date + stay_days` 生成，住院天数取值 0–20 天（K7/K11 说明口径）。统计窗截止 2025-06-30，凡计算出的出院日期超出窗口的病例被**压到窗口末日**，直接堆积在 06-30。
2. **入窗侧无补偿**：窗口首日 2025-04-01 之前入院的在院患者未被纳入，导致 4 月出院人次天然偏低；窗口未形成"稳态流入—流出"闭环。
3. **月度分布印证**：分月出院人次为 4 月 314 / 5 月 511 / 6 月 675（含 06-30 的 190 例），呈单调右偏，正是截断堆积的典型形态。

**影响评估**

| 受影响对象 | 影响 |
| --- | --- |
| M08 出院人次（统计期累计） | 不影响：1,500 为全量，堆积不改变合计 |
| M08 日粒度趋势图 | 影响：06-30 出现异常尖峰，若前端不做标注会被误读为"月末突击出院" |
| M33 收入环比 / 月度住院指标 | 影响：6 月基数虚高，环比结论失真 |
| M10、M12 | 轻微：床日与平均住院日基于全量病例，堆积不改变合计（14,317 床日、9.54 天） |

**处理建议**

1. **规则侧**：`QR-DQ-19` 增加"窗口末日豁免"配置项（如 `exempt_edge_days = 1`），豁免期内仅记录不告警；阈值由固定 ±20% 改为"剔除豁免日后 ±20%"。
2. **数据侧**：为每条住院记录新增派生标记 `is_window_edge`（出院日期 = 统计窗首日或末日），DWS/ADS 层随指标落库。
3. **展示侧**：住院类日/月趋势图强制附"窗口首尾效应"注释，06-30 数据点加角标说明（对应 K6）。
4. **文档侧**：月度住院指标口径说明统一引用《指标口径手册》第 6 章 K6，测试用例 TC-FN-037 校验该注释是否存在。
5. **生产侧替代方案**：生产环境以"自然月全量 + 滑动窗口（统计期末日 ±7 天）"双口径复核，本项告警不阻断验收。

**结论**：告警成立但不构成数据缺陷，判定为**可接受告警（Accepted Warning）**，需在阶段二关闭规则阈值并补充标记字段后转为"通过"。

#### 3.3.2 异常二：就诊登记费用与收费流水合计差异远超容差（提示级）

**现象**

| 口径 | 载体 | 计算 | 实测值 |
| --- | --- | --- | --- |
| 登记口径（门诊） | `his_outpatient.fee_amount` | 合计 3,826,341.68 元 ÷ 9,000 人次 | **425.15 元/次** |
| 流水口径（门诊） | `his_charge.amount`（`visit_type='门诊'`） | 合计 26,930,553.74 元 ÷ 9,000 人次 | **2,992.28 元/次** |
| 差异 | — | 2,992.28 ÷ 425.15 − 1 | **约 +603.8%（约 7.04 倍）** |

> 差异幅度算式透明可复算：`2,992.28 ÷ 425.15 = 7.0382`，`−1 = +603.82%`。该数值为两个实测值的算术派生结果，非独立测量值。

**原因分析**

1. **两路径独立生成**（K1）：模拟数据生成器分别产出"就诊登记汇总费用"与"逐笔收费流水"，二者未做勾稽约束。流水口径门诊平均 2.98 行/次、住院平均 11.49 行/次，累加后金额量级自然远高于单行登记值。
2. **口径本义不同**：登记口径是挂号/就诊登记时的一次性汇总字段；流水口径是收费项目逐笔明细之和。真实医院中两者应可勾稽，但模拟数据放弃了一致性约束。
3. **业务量级抽查**：流水口径门诊收入 26,930,553.74 元对应 9,000 人次，折合人均 2,992.28 元，若为真实门诊显著偏高——进一步印证其为生成参数驱动的模拟值。

**影响评估**

| 受影响对象 | 影响 |
| --- | --- |
| M03 门诊次均费用、M13 住院次均费用 | 必须使用登记口径，禁用流水口径（《指标口径手册》2.2） |
| M07/M15/M16/M17–M22/M30 | 必须使用流水口径或财务口径，禁用登记口径 |
| "人次 × 次均费用 = 收入"类反推 | **禁止**：两口径不可互换，反推结果必然错误 |
| 验收标准"指标计算准确率 ≥99%" | 须按口径分组统计，跨口径比较不计入准确率 |

**处理建议**

1. **规则分级**：`QR-CHG-03` 在演示环境固定为**提示级（不阻断）**并记录差异值；生产环境切为**阻断级**（差异 >5% 阻断下游）。
2. **口径显式化**：每个指标在 `metric_def` 与前端图表角标显式标注口径来源（登记 / 流水 / 财务），接口返回字段增加 `metric_caliber` 枚举。
3. **展示隔离**：同一图表内不得混用两种口径；提供口径切换开关但切换时整体重绘（对应《指标口径手册》4.3）。
4. **测试约束**：指标断言用例（TC-MET-*）严格按手册指定口径取数，禁止测试脚本自行改用其他口径"凑"基线值。
5. **文档同步**：`QR-CHG-03` 的差异值与处理约定须与《指标口径手册》第 6 章 K1 保持同一数值表述。

**结论**：属**已知数据特征导致的预期差异**，判定为提示级、不阻断阶段一/二/三推进；须以缺陷 DEF-001 跟踪，在演示环境始终保留可见的口径提示。

## 4. 指标口径测试

### 4.1 测试方法

**核心方法：固定统计期 + 明细重算 + ADS 比对**

| 步骤 | 内容 |
| --- | --- |
| S1 | 固定统计期 `2025-04-01 ~ 2025-06-30`（91 天，闭区间），不引入其他时间条件 |
| S2 | 依据《指标口径手册》第 4 章对应指标的"来源"列，确定唯一取数表（S1~S6 或 `dim_*`） |
| S3 | 绕过 ADS 层，**直接对 DWD/DWS 明细执行手册给出的原始 SQL 公式**，得到"独立重算值" |
| S4 | 查询 ADS 指标结果表（或 `/metric/{code}/values` 接口），得到"平台输出值" |
| S5 | 按容差规则比对，判定通过/失败；失败须给出三段式证据：重算值、平台值、差异量 |
| S6 | 对"待数据源补充"类指标（M04/M05/M27/M28/M29），断言接口返回 `null` 且前端展示"数据源待补充"，而非断言数值 |

**容差约定（与《指标口径手册》第 5 章一致，不得放宽）**

| 指标类型 | 容差 | 判定方式 |
| --- | --- | --- |
| 金额类（元） | **±0.01 元** | `ABS(平台值 − 基线值) <= 0.01` |
| 比率类（%） | **±0.01 个百分点（pp）** | `ABS(平台值 − 基线值) <= 0.01` |
| 人次 / 床日 / 例数 | **必须完全相等** | `平台值 == 基线值`（整数精确匹配） |
| 指数类（CMI、消耗指数） | 按手册给出的 4 位小数精确到末位 | 保留位数须与手册一致（如 0.9174） |

**判定纪律**

1. 基线值**只**允许取自《指标口径手册》第 5 章汇总表；测试代码中的期望值须以常量文件形式集中管理，标注手册章节号。
2. 若平台值与基线不符，**先查口径实现是否取错源表**（登记/流水/财务混用是最常见原因），再判定为缺陷。
3. 比率型指标须附值域断言 `0 <= value <= 100`（《概要设计》4.4）。
4. 每个指标断言用例必须复现同一结果三次（连续三个批次），验证幂等性。

### 7.3 压测脚本设计要点

| 要点 | 说明 |
| --- | --- |
| 鉴权前置 | k6 `setup()` 中调用 `/auth/login` 获取 token，`default()` 复用；避免压测中把登录接口变成瓶颈（登录单独用 TC-PF-005 的前 10% 流量覆盖） |
| 参数化 | 统计期、dept_code、metric_code 从 CSV 数据池随机取，覆盖 10 科室 × 33 指标 × 3 月组合 |
| 思考时间 | 使用 `sleep(1~3)` 模拟真人节奏，避免"机器风暴"造成错误率虚高 |
| 断言 | 每个请求断言 HTTP 200、`code=0`、`data` 非空、响应体大小在合理区间；失败计入 `http_req_failed` |
| 阈值 | k6 `thresholds` 声明：`http_req_duration{p(95):3000}`、`http_req_failed:rate<0.005`，超阈值返回非 0 退出码以便 CI 判定 |
| 阶梯加压 | stages：10 VU/1 min → 25 VU/2 min → 50 VU/3 min → 保持 50 VU/5 min → 归零 1 min |
| 数据隔离 | 压测库独立（`medical_ops_test`），压测前后各跑一次数据量校验，确保无数据污染 |
| 导出与查询分离 | 导出为异步任务，压测只压"提交 + 状态轮询"，不压大文件下载流，避免带宽干扰判断 |
| 监控采集 | 同步采集 MySQL `SHOW GLOBAL STATUS`、慢查询、后端 CPU/内存、连接池使用率，与 k6 结果按时间戳对齐 |
| 可重复 | 脚本版本化，固定随机种子，记录压测机规格，保证结果可对比 |

### 9.2 评分标准（四维评分）

| 维度 | 权重 | 满分判定条件（得 1 分） | 扣分条件（得 0 分） |
| --- | --- | --- | --- |
| 1. 意图正确 | 25% | 正确识别为"数据查询/趋势/构成/排名/归因"，且未答成闲聊或知识问答 | 意图误判，如把"趋势"答成单值，或答成口径解释 |
| 2. 指标正确 | 25% | 命中唯一且正确的指标编号（含同义词映射正确，如"病床使用率"→M11） | 指标错、指标不唯一、把待补字段指标算成 0 而非提示 |
| 3. 维度正确 | 25% | 科室/时间/号别/费别/病种等维度与预期完全一致（含时间解析正确） | 维度缺失、时间解析错（如"上月"解析为 2025-05 而非 2025-06）、越权维度未拦截 |
| 4. 数值正确 | 25% | 返回数值与基线一致（金额 ±0.01 元、比率 ±0.01pp、人次/床日精确相等） | 数值偏差超容差、数值缺失、口径取错（登记/流水/财务混用） |

**单条得分**：`得分 = (0.25×V1 + 0.25×V2 + 0.25×V3 + 0.25×V4)`，V∈{0,1}
**整条判定**：得分 = 1.00 记为"完全正确"；得分 ≥ 0.75 记为"基本正确（可接受）"；得分 < 0.75 记为"错误"。

### 9.3 准确率计算与判定

```
准确率 = 完全正确条数 ÷ 有效测试条数 × 100%
（辅助指标）可接受率 = (完全正确 + 基本正确) ÷ 有效测试条数 × 100%

有效测试条数 = 总条数 − 无效条数
无效条数 = 问题本身有歧义、期望答案在数据集中不可算（且未标注为"应提示待补充"）的条目
         —— 无效条目须在测试集中显式标记，且不得超过总条数的 10%

判定线：准确率 ≥ 85% 为达标（《项目说明》第二章目标 5）
```

**分主题与分问法统计要求**

| 统计维度 | 要求 |
| --- | --- |
| 分主题 | 8 个主题分别给出准确率，任一主题 <70% 视为局部不达标，需提交 Prompt/模板改进方案 |
| 分问法 | 6 类问法分别给出准确率，归因类与排名类允许单独设定子阈值（建议 ≥75%） |
| 分指标 | 标注出现频次最高的错误指标对（如 M19 与 M20 混淆），作为改进输入 |
| 安全性 | 越权问题与注入问题**必须 100% 拦截**，不计入准确率但作为一票否决项 |
