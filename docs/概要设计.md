## 1. 设计目标与原则

| 原则 | 落地方式 |
| --- | --- |
| 分层解耦 | 采集/计算/服务/展示四段解耦，ADS 结果表是唯一出口 |
| 口径唯一 | 指标只在 ADS 层实现一次，接口与前端只取数（《指标口径手册》） |
| 接口统一 | 全部能力以 `/api/v1` RESTful 暴露，统一响应包与错误码 |
| 权限内建 | JWT + RBAC + 科室/院区行级数据权限 + 操作审计，非事后补救 |
| 可观测 | 采集任务、指标计算、接口调用、AI 调用全链路留痕（批次号 + trace_id） |
| 容器化 | 一键 `docker compose up` 起 MySQL、后端、前端（《部署运维手册》） |
| 可扩展 | 新增主题 = 新增 DWS/ADS 表 + 指标定义 + 页面配置，不改动核心框架 |

## 2. 总体架构

### 2.1 逻辑架构（四层 + 两侧支撑）

```

└───────────────────────────────┬──────────────────────────────────────────┘
                                │ HTTPS / JSON（Nginx 反代 + JWT）
┌───────────────────────────────▼──────────────────────────────────────────┐
```

## 4. 数据仓库设计概要

### 4.1 分层职责

| 层 | 表前缀 | 职责 | 数据特征 | 保留策略 |
| --- | --- | --- | --- | --- |
| ODS | `ods_` | 贴源存储，字段与源系统一致，不做业务加工 | 原始值含隐私字段 | 全量保留 2 年 |
| DWD | `dwd_` | 去重、空值处理、编码标准化、隐私脱敏、宽表 | 一行一业务事件 | 永久（分区按月） |
| DWS | `dws_` | 按主题 + 粒度聚合（日/月） | 一行一维度组合 | 3 年 |
| ADS | `ads_` | 指标结果表，直接支撑看板与接口 | 一行一指标一维度 | 永久 |
| DIM | `dim_` | 公共维表与字典 | 缓慢变化维（SCD1） | 永久 |

### 4.3 指标计算链路

```
dim_* 初始化（科室床位数、费别归类、DRG 权重）
  ↓
dws_op_visit_1d / dws_ip_visit_1d / dws_revenue_1d / dws_bed_1d / dws_drg_1d
  ↓ 指标 job（按 metric_def 的 SQL 模板执行）
ads_kpi_*（每行含 metric_code、dim 组合、stat_period、metric_version、calc_batch_id）
  ↓
质量 job（规则校验 + 基线对比）→ 通过则发布，不通过则阻断 + 告警
  ↓
服务层读取 /dashboard、/analysis
```

### 4.4 数据质量校验点（与 ETL 阶段绑定）

| 阶段 | 校验点 | 拦截方式 |
| --- | --- | --- |
| 采集后（ODS） | 行数波动率、主键唯一、必填非空、日期格式、值域 | 严重级阻断入库 |
| 加工后（DWD） | 编码映射成功率、脱敏完整性、日期逻辑（出院≥入院） | 严重级阻断下游 |
| 汇总后（DWS） | 与 DWD 合计对账（金额/人次） | 差异 > 0.1% 阻断 |
| 指标后（ADS） | 与基线值比对、比率型指标值域（0–100%）、跨表一致性 | 告警 |

### 5.2 统一响应与错误码

```json
{ "code": 0, "message": "success", "data": { }, "trace_id": "f3a9c1e0" }
```

| code | 含义 | HTTP |
| --- | --- | --- |
| 0 | 成功 | 200 |
| 40001 | 参数校验失败 | 400 |
| 40101 | 未登录/令牌失效 | 401 |
| 40301 | 无权限（角色） | 403 |
| 40302 | 数据越权（科室/院区） | 403 |
| 40401 | 资源不存在 | 404 |
| 50001 | 服务内部异常 | 500 |
| 50101 | 指标不存在或口径版本不支持 | 400 |
| 50301 | 大模型调用失败/超时 | 503 |

### 5.3 请求处理链路

```
Nginx → 中间件(trace_id/CORS/耗时日志) → 依赖注入(解析JWT→载入用户→注入数据权限范围)
      → 路由 → Service（口径校验 + 缓存查询） → 只读 SQL（ADS/DWS）
      → 审计埋点（谁/何时/查了什么/导出了多少） → 统一响应封装
```

### 5.4 性能设计

| 手段 | 说明 | 目标 |
| --- | --- | --- |
| 预聚合 | 所有指标在 ADS 落库，查询期只做过滤与排序 | 单指标查询 ≤ 300 ms |
| 复合索引 | ADS 表按 `(stat_date, dept_code, metric_code)` 建联合索引 | 范围查询走索引 |
| 进程内缓存 | 驾驶舱全量数据 TTL 5 分钟；指标字典 TTL 1 小时 | P95 ≤ 1 s |
| 分页与限流 | 明细类接口默认 20 条/页，导出走异步任务 | 防大结果集拖垮服务 |
| 连接池 | SQLAlchemy pool_size=10, max_overflow=20 | 并发 50 稳定 |

## 7. 智能分析设计概要

### 7.1 NL2SQL 流程

```
用户问题（如"上月呼吸科床位使用率趋势如何"）
  → 意图识别（指标 + 维度 + 时间 + 过滤器）→ 匹配 metric_def（M11 + dept=HN + 2025-06）
  → SQL 生成（基于模板 + 指标口径，非自由拼 SQL）
  → 安全校验 guard.py（白名单表/字段、只读、强制 limit、禁止 DDL/DML/子查询注入）
  → 执行 → 结果集（≤ 500 行）
  → 图表类型推荐（趋势→折线；对比→柱状；构成→饼图）
  → 文字结论生成（含数值、环比、异常提示）
  → 返回 {sql, data, chart, insight}，全程写 ai_qa_log
```

- **模板优先**：优先从 `metric_def` 的口径模板生成查询，大模型只负责语义解析与文案，避免口径漂移与注入风险。
- **失败兜底**：意图不明确时返回候选指标清单与追问引导；SQL 校验失败返回安全提示，不暴露底层结构。

### 7.2 报告生成

- 模板：周报（7 天）、月报（自然月）、专题（指定指标集）。
- 组成：章节结构（总览 / 门诊 / 住院 / 收入 / 效率 / 病种 / 风险提示）+ 图表配置 + 文字结论 + 数据附表。
- 输出：Markdown 预览 → PDF/Excel 导出（reportlab/openpyxl）→ 订阅推送（站内信/邮件）。

### 7.3 异常归因

指标环比波动超过阈值（默认 ±10%）触发：按科室、号别、费别、病种逐维下钻，计算各维度对总变动的贡献度，输出 Top3 归因项与建议话术。

### 7.4 安全边界

| 约束 | 说明 |
| --- | --- |
| 数据出境 | 仅发送聚合结果、指标名、维度名；明细行与隐私字段不出网 |
| 提示词保护 | Prompt 模板与系统指令不入库、不进前端 |
| 权限继承 | AI 问数继承当前用户的科室数据范围，问数结果不得越权 |
| 留痕 | 每次调用记录问题、生成 SQL、执行耗时、返回行数、模型与版本 |

## 10. 安全设计概要

| 层面 | 措施 |
| --- | --- |
| 传输 | 生产启用 HTTPS；Nginx 强制跳转，HSTS |
| 认证 | JWT（Access 2h / Refresh 7d），密码 bcrypt(cost=12)，登录失败 5 次锁定 10 分钟 |
| 授权 | RBAC 功能权限 + 数据权限（科室/院区行级过滤，由依赖注入统一追加 `dept_code IN (...)`） |
| 输入 | Pydantic 强校验；SQL 全部参数化；NL2SQL 走白名单 guard |
| 隐私 | DWD 起全链路脱敏；ODS 仅 DBA/ETL 账号可读；导出含个人标识时二次鉴权 |
| 审计 | 登录、查询、导出、权限变更全量留痕，日志保留 ≥ 180 天 |
| 密钥 | 数据库口令、JWT 密钥、LLM Key 全部走环境变量/`deploy/.env`，禁止入库入仓 |
| 越权防护 | 接口层强制校验 `dept_code` 归属；横向越权测试纳入测试用例 |

## 12. 关键技术决策记录（ADR 摘要）

| 编号 | 决策 | 备选 | 理由 |
| --- | --- | --- | --- |
| ADR-01 | 指标在 ADS 预聚合落库 | 查询期实时聚合 | 满足 ≤3 s 响应；口径唯一；降低源库压力 |
| ADR-02 | 登记口径与流水口径显式分离 | 强对账后合并 | 模拟数据两路径独立生成，强合并会产生错误指标 |
| ADR-03 | NL2SQL 采用"模板 + 语义解析" | 全自由文本生成 SQL | 避免口径漂移与注入风险，可控可审计 |
| ADR-04 | DRG 使用维表模拟分组 | 引入开源分组器 | 数据集无分组结果，维表映射即可跑通链路且易替换 |
| ADR-05 | 单库多 schema 分层（同库前缀区分） | 分库分实例 | 数据量小（<5 万行），单实例足够，降低部署复杂度 |
| ADR-06 | FastAPI 同步 SQLAlchemy 会话 | 异步 ORM | ADS 查询为简单聚合，同步更易维护；AI 出站单独用 httpx 异步 |
